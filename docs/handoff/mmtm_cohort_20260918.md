# 小队列 MMTM A / A+LOOK：有限适配协议

2026-09-18，基于用户授权负责人自主设计、优先回答老师“已有方法是否能加LOOK”的问题登记。此协议在本配置训练前明确；不是原MMTM视频/骨骼系统复现，也不是用R&B的零初始化门控代替作者实现。

## 要回答什么

A是加入作者MMTM门控的眼科双路分类宿主。对同一个已训练并冻结的A，比较不矫正、PCA自由均值＋正收益树、自由低秩残差＋正收益树。两个缺失状态分别报告Macro-F1差值、参与者级配对区间及AUROC/NLL/Brier。若最终不启用矫正、改善很小或次要指标恶化，同样保留；开发集选优的非下降不等于泛化获益。

这个问题不能由已完成的换骨干实验或搜索集合包含关系直接回答，因此只新增一个代表宿主，seed3416，不加门控层数/倍率/种子网格。已有R18/R50结果仅作背景参考，不重训，也不把不同宿主间差值当严格单因素因果效果。

## 固定配方与合法差异

- 原小队列青光眼1,264 train / 296 dev，参与者划分、224二维CFP/OCT输入及数据审计SHA不变；test封存。
- 两路ResNet18，公开ImageNet V1初始化，最终仍在Stage4后拼接投影、每眼池化、参与者汇总、单分类头。
- 两路Stage3后加入一次MMTM：各路空间均值→拼接→共享Linear/ReLU→各路Linear/sigmoid→乘回特征，再各自进入Stage4。ratio=4、gate_scale=1，作者随机Linear初始化。作者源锁定`1c81cfefad5532cfb39193b8af3840ac3346e897`；scale2和identity初始化不混入本配置。
- 这是双二维医学输入的门控模块适配，不保留原视频/骨骼编码器；不声称完整论文系统、公平参数量或复现作者性能。
- 保持现有complete-input宿主训练配方：每次16人、累积128人；AdamW，预训练1e-4、新层1e-3，wd1e-4、clip5、FP32；最少8轮、patience15、最多100轮保护上限、warmup5。不因赶时间改停止标准，不新增缺失训练。
- 训练后宿主冻结；两拟合均自由均值、rank32、空间x16，保持各前缀训练PCA-GCV正则选择和9处合法修正位置。Stage3修正发生在门控前，其下游必须重新执行门控。完整参考/缺失前缀缓存仍以新宿主及源SHA独立绑定，不复用旧宿主特征。

## 工程与发布门槛

本次实现显式MHD节点，共享描述符/压缩只算一次，门控参数各自唯一归属新层学习率。普通PyTorch拓扑重放对照输出/梯度；真实网络更新、完整模型与AdamW恢复的下一更新、BN及Node身份检查。既有宿主默认路径必须不变。

CPU检查不代替真实224输入GPU预检。先在LOOK GPU0核验完整dev、实际训练更新、完整状态恢复及资源余量，才接原cohort_delivery有限pipeline。此配置仍使用原单GPU锁和sequence锁，不增加资源调度器。故障隔离保留日志/检查点；阶段完成后自动接PCA→两拟合树→重放/统计/累计报告，阶段未验收不称成功。大权重和参与者资产留授权存储，GitHub只公开汇总与SHA。
