# 持续模型发现与自动研究流程

用户于2026-09-12授权持续自动发现、筛选模型，并按既定研究范围推进。
日常检查、验收、登记、恢复、汇总不要求用户逐次操作。

## 两种节奏

模型库存持续更新，研究轮次保持不可变。新模型的出现不改变已经开始的
比较；同一轮里各方法必须继续使用锁定的父模型、数据和统计协议。
下一轮可纳入新完成模型，但不能把不断尝试后获得的最高分当作独立证据。
无需设置一个跨疾病通用的F1门槛；技术验收与开发集方案提名是不同状态。
只有模型名字、shape或分数相似不构成可复用依据。

## 已部署的CPU控制器

入口：`python -m look.studies.autoresearch --config <binding.json>`。
默认每30分钟核查，`--once`执行一次。服务器路径通过独立绑定传入。
既有模型训练、GPU原子领取与资源准入仍由Model_Training调度器管理。

1. 持续扫描模型队列spec，核对SHA并去重，记录架构、维度、任务、种子
   及来源。损坏队列单独记账；test来源不明的模型不能自动准入。
2. 对锁定catalog调用原生训练验收器，检查实际文件SHA、配置、停止规则
   和保存的验收证据。文件完整核验不是重新执行一次模型预测。
3. 同组所有候选验收后，按既定开发集排序自动提名，永久保存方案。
   未完成、失败或撤销验收会阻止该组继续，不妨碍其他组和基础模型训练。
4. 自动登记种子3417/3418的原方案重复。只变种子和对应来源记录；学习率、
   损失、初始化、训练规则、数据和预处理不变。run由公共注册器分配，
   重启保留原run ID。没有完整验收不会标训练完成。
5. 生成不可变重复训练queue和`native_work_feed.json`，由资源调度衔接消费。
   这不是另一套GPU领取机制；不修改正在运行的queue，不自动取消旧任务。
6. 自动产生中文状态表和阶段变更事件。持续发现记录与本轮科研结果分开。

控制器持有共享文件锁防止重复常驻进程，tick另有原子锁。重启重新核查
来源，不依靠过期心跳抢任务。协议/spec变化进入需处理状态，不能覆盖旧锁。

## 已接通的执行阶段

父方案提名后，重复种子由常驻工作调度器直接消费；不依赖三小时检查临时
手工接队列。每个疾病/架构的两种模态及三个种子全部验收后，自动登记
三个融合位置，共九个项目宿主。整个固定范围共81个宿主。

项目执行包含独立副本、完整开发预测重放、宿主训练与恢复、LOOK及匹配
对照、开发评价、统计和中文说明。实时GPU资源验收在获批后、正式训练前
运行；若预检失败，该项隔离，不能跳过验收。尚未完成的父模型是数据依赖，
不再是等待开发适配器。外部数据与独立test仍有单独准入门槛。

## 异常规则

- 明确的基础设施中断：使用原调度器确认旧step结束，按同run的有效完整
  断点恢复；不改配置，不伪造新种子。
- OOM/坏文件/确定性代码错误：隔离受影响任务，生成处理记录；验证版本化
  修复后再恢复。健康任务继续，不能盲目循环重跑或擅自缩小batch。
- 性能不理想：保留为研究结果，不等同技术失败，不自动剔除。
- 新架构缺接口、新数据缺访问：登记待验收；不能直接套用另一个模型的
  stage映射、二维输入或医学标签。

全部产物分别保存架构、训练配置、run、父模型与研究轮的映射。限制数据、
预测和模型留在授权存储，GitHub只保存代码、协议与可披露汇总。

## 父模型项目副本

`look.models.native_materialization`提供原生训练格式的独立项目副本与严格
完整模型加载。先运行原生验收，再复制best、spec、开发预测、历史和来源
记录；逐文件SHA核对后原子发布，禁止硬链接和回写原模型。原source receipt
作为来源证据保留，项目副本有自己的manifest，不冒充包含原全部训练文件。
副本不含last优化器状态，不能用于声称完全恢复原训练。复制和严格state_dict/
Node ID加载仍不等于全开发集预测重放；`selected_prediction_replay=false`
保持明确。副本发布随后由项目执行器完成全开发集数值重放；重放失败不得训练宿主。
尚未完成筛选的模型不会提前复制成正式父模型。

## 2026-09-13：真实项目执行链路

新增 `look.runtime.project_dispatch` 负责消费原生重复训练和项目工作清单，
并在账号运行及待批GPU总数低于有效上限时申请单张A10080/48h。
最多同时占用两份工作流allocation；其余基础模型owner保持原状。
获批后先做完整资源预检，再执行真实训练；无可执行工作就正常退出。
请求身份不明、源文件变化、领取冲突、资源失败均保留证据，不盲目重试。

每一对匹配父模型依次执行：独立副本 → 完整开发集数值重放 →
融合宿主训练与完整断点 → 选中宿主重放 → 冻结宿主和BN →
完整训练特征PCA → 逐级LOOK选择/单末级/全部开启 →
训练集拟合偏置及logit仿射对照 → 匹配开发集评价 → 配对统计与中文说明。
不能用登记数量、step退出码或检查点存在代替训练和评价验收。

宿主保持原LOOK的“在起点汇合、之后单主干”结构。ResNet50使用stage2、
stage4、features；DenseNet121使用denseblock2、denseblock4、features；
Swin-B使用stage2、stage4、features。它们是架构对应位置，不声称有效
深度或参数预算相等。后半网络和任务头固定从CFP父模型复制，不按新性能
选择初始化来源。两路前半网络分别来自各自的独立完整模型。

本次宿主训练配置在新分数产生前固定：AdamW、未加权CE、backbone1e-4、
融合/头1e-3、WD1e-4、effective batch128、microbatch16、FP32、梯度裁剪5、
5轮预热+100轮余弦计划、至少8轮、连续15轮macro-F1未改善停止。
100轮仍未满足停止条件标需处理。前述LR/WD/batch/预热取自既有LOOK配置；
FP32和显式梯度裁剪、从训练后CFP父模型复制suffix为本次固定实现约定，
不冒充某篇医学论文完整复现。原生模型保持各自已登记的文献/探索配置。
父模型预处理逐模态原样复用，数据抽样不改变，宿主不再增设搜索。

LOOK继续使用完整训练特征、通道标准化、增量PCA、GCV岭回归、按前向
顺序的同层联合写回与开发集可选启用。空间降采样4/8/16；维数
8/16/32/64/96/128/192/256/384/512，最大秩512（受样本秩约束）。
单末级只在参与者feature处修正；all_on使用相同候选但不能关闭层。
偏置和仿射对照只用训练输入拟合同宿主的完整logits，不额外用标签。
归一化均值填充是零值输入，完整输入不启用LOOK；不以相同完整预测
作为新的泛化性能结论。缺失比例掩码依旧按参与者固定，双眼共同缺失。

原始训练/开发预测、父模型、完整断点和拟合产物只存授权服务器。
GitHub同步代码、配置规则及不含参与者信息的验收记录。
每个宿主的bootstrap表是开发诊断的比较族，整个研究跨宿主汇总另按
冻结的模型、种子和位置权重处理，不能把单宿主区间冒充全研究校正。

本链路当前针对已获准的UKB开发研究。独立test必须先完成全体模型和
比较定义锁定及数据暴露审计，不能因为工作流自动运行就提前访问。
MMC-AMD、Harvard-30K数据和EDRL适配仍各有明确的数据/方法验收要求；
不会标成已完成或冒充主流程中已验证的方法。
