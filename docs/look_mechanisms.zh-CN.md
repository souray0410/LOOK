# LOOK：UKB机制验证补充协议 v1

本协议落实“宿主先完成训练，再冻结并拟合LOOK”。适用当前大队列、三疾病、ResNet50 / DenseNet121 / Swin-B、middle / deep / features、3416–3418，共81个原始宿主。旧任务身份、数据划分、MHD_Framework V4和健康allocation保持不变。此处的验收是执行标准，不要求LOOK优于对照。

|---|---|---:|---|
| A | 原81个宿主及六类对照 | 沿用旧清单 | 父模型、宿主、冻结、拟合及dev全链路验收 |
| B | 完整继续训练 / 缺失鲁棒继续训练 | 162 | 对应原宿主验收；新宿主分别重拟合PCA、LOOK和旧对照 |
| C | CFP/OCT蒸馏 | 162 | 原宿主作冻结教师；对应单模态父模型作学生初始化 |
| C | CFP/OCT仅CE继续训练 | 54 | 按疾病、架构、种子、模态去重；融合位置共享引用 |

配置计数器产生378次新增神经网络训练和7,182个逻辑工作位置。后者包括1,620个机制位置、5,184个样本曲线位置，不等于独立模型、参与者或新增神经网络训练。机制中的只读写回/仿射视图、样本曲线中的324个100%视图分别标记；100%两条曲线引用同一原全量拟合。三组100%子集不重复运行。新宿主的LOOK/原对照是对应B任务的验收后续阶段，另记拟合产物，不能因其宿主训练结束就计整个任务完成。

每个宿主通过后立即可释放对应任务。沿用同一个原子claim、账号提交锁、allocation journal及最多2个LOOK工作allocation；不另建竞争性GPU调度器。原任务由其原不可变源码执行。新allocation交替领取原主线和已就绪补充；补充内先训练、再机制、再样本曲线。调度不读取性能排序。

## 训练制度与成本

B/C统一AdamW，backbone LR=1e-5、头/融合LR=1e-4、WD=1e-4，FP32，microbatch16、有效batch128，clip5；5轮预热+100轮余弦计划，至少8轮，15轮主指标无严格改善判平台。100轮仅保护上限。全量组与缺失鲁棒组均按dev完整/缺CFP/缺OCT macro-F1等权平均选优；学生按自身模态dev macro-F1选优。两个宿主组均从同一个原宿主的dev最佳点开始，重置优化器/调度器，保留模型/BN初值。缺失采样对参与者等概率选择三状态，使用可恢复的独立随机流，双眼一起缺失。

蒸馏为 CE + 4 KL(softmax(teacher/2) || softmax(student/2))。教师只在train生成软目标，参数与BN冻结；只CE学生具有相同初始化和训练制度。学生不读取缺失模态。继续训练不保证固定轮数相同。

产物保留模型、BN、优化器、调度器、随机流、数据进度及Node ID。暂停后沿用同run ID；失败与未平台不能伪装成完成。独立资源预检包含25次更新（5预热+20测量）、dev前向、保存/重载后下一步一致性。实际父模型预检在该父模型可用后进行，不能用32px合成验收代替224px正式资源准入。未知共存负载时保留健康旧任务并延后预检。

整卡预算 min(0.875T,T−10GiB)，按已有负载+1.2×实测峰值+2GiB准入；worker内存100GiB内保留15%余量。PCA/潜在特征内存还要按完整train规模估算，明确估算与实测。每个任务的当前批次10次预热、50次同步计时报告中位数/IQR；存在其他GPU进程或监测未知时不宣称速度优势。另存拟合、诊断、训练、重启attempt成本，不假定LOOK更快。

## 机制定义

- 独立拟合：每层拟合时不应用上游修正，最后同时应用已拟合各层。
- 打乱：三组标签无关的固定无自配对置换，按观察到的眼数分层，双眼整体移动且眼内顺序不变。映射跨层保持一致，包括眼级特征转为参与者池化特征之后。单例眼数层不能无自配对时显式报技术不可行。
- 写回限制：只读关闭与受限结构重拟合分别报告。融合前屏蔽可用/缺失来源；融合后保持原结构。无可分支位置标为不适用，不把零残差误解为无效。
- 受限重拟合：在原选中PCA子空间下最小化指定写回分支的重构误差，保持原LOOK的岭系数。Gram矩阵包含PCA恢复、标准差与分支掩码；不为该消融新增dev搜索。
- MLP：两层线性/ReLU/零初始化输出，无BN/dropout；选择使参数量最接近原仿射映射的正整数隐宽。仅拟合特征残差，标签不进入目标；90/10参与者内部划分选epoch，再在完整拟合集精确epoch重拟合。AdamW1e-3、WD1e-4、batch256、最多200轮、20轮相对MSE改善不足1e-4停。原宿主始终冻结。
- 仿射等价：若残差是 zW+b，则直接输出是 z(I+W)+b。残差岭惩罚 λ||W||² 对应直接映射 λ||B−I||²，不能与 λ||B||² 混称同一正则。等价验证不是新增优效假设。

E的三组子集按参与者稳定标识的独立哈希排序嵌套，标签不参与选取，记录病例数与清单SHA。标准化/PCA/回归只读当前子集。固定配置秩不足直接不可行，不缩维；重新选择曲线沿用原dev选择规则，与固定曲线分开。较低特征误差不等于较高分类性能；同时报告残差范数、逐层误差和预测错误转移。

## 统计、test与迁移

主输出是宿主/学生最终分类，完整、缺CFP、缺OCT分开，混合缺失率0.2/0.4/0.6/0.8/1.0作次要分析。没有Radon_Bridge分支F1平均指标。主要比较类型在新性能前写入comparisons.json；实际模型SHA与权重之后绑定，缺失格子不重新归一化。旧六对照族保留，新训练制度、蒸馏、机制、样本效率族独立记录。

10,000次参与者bootstrap；同疾病模型配对身份与标签必须一致，跨疾病按参与者并集共享重采样 multiplicity，保留重叠。普通95%、族内max-|t|与全研究max-|t|区间分别给出；零方差标记，±1pp不因结果变动。开发集选优影响未消除。疾病/架构/位置/种子原始行全部保留，不能用平均掩盖反例。

`mechanism_test prepare`只生成注册表，未完成训练或独立dev重放时不生成解封。正式入口先核验锁、全部模型、比较、数据/暴露审计SHA，再构造test数据；训练入口继续拒绝test。全部正式推理需从冻结产物重载，不拟合任何目标端参数。当前新增工作保持test关闭，原始81任务也不因补充完成而单独提前开test。

数据审计记录中心、设备、时间和自然缺失字段的可得性；当前成对缓存不能估计整个UKB的自然缺失率。未知字段/伦理信息明确待补，不推断为不存在。本轮不重划分中心，也不把随机划分写成跨医院验证。

后续适配合约区分 method_replication（新数据按锁定规则重训/拟合）和 frozen_transfer（输入、标签、节点兼容后冻结直接评估）。至少绑定数据/划分/标签/预处理SHA、维度、节点映射。新数据不沿用不合适的UKB标签或切片假设。

最终以“主张—匹配实验—证据—反例—不确定性—迁移限制”组织结果；不承诺期刊录用或临床效用。

全范围统计在所有任务验收或技术不可行原因明确后，通过一次8核/128GiB的CPU作业执行，避免在Ibex登录节点运行大规模bootstrap。任务提交有持久化意图记录，状态不明不重复提交。相同差值虽去重计算，仍保留它所属的全部原/新比较族与相应区间。

监控首次完整校验SHA后，使用收据及证据文件inode/大小/mtime作为缓存失效条件，避免每30分钟反复读取数百GB已完成权重。正式父模型加载、最终分析和test仍完整核验，不用监控缓存授予新训练资格。

派发器接替保留原TTY/session leader及其salloc子进程：新CPU管理器先只读校验并等待；在同一账号提交锁内复制旧申请账本、仅暂停旧CPU派发器，再激活新派发器。旧allocation owner、训练进程和源码不受信号影响。旧管理器的所有直接子进程退出后才清理该暂停的CPU进程；申请ID、claims、每工作流上限不变。


独立dev重放入口：`python -m look.evaluation.mechanism_test --replay-development --models <test_preparation.json> --output <independent_replay>`。逐模型重新加载已选完整MHD及修正产物，核对全部评价视图、参与者、标签、缺失状态、预测类别和logits（atol=1e-6、rtol=1e-5），单独输出模型注册表，不改历史训练摘要。该入口不拟合任何参数；正式test仍需全研究、比较和数据审计共同锁定，不能因为重放通过就自动解封。

Ibex实际接替发现tmux会自动恢复被SIGSTOP暂停的面板进程。旧CPU派发器仍承载现有salloc的终端，因此不直接终止；独立会话保护进程仅暂停该CPU派发器，保留所有子进程，待其全部结束再清理。新GPU任务使用独立不可变快照。会话保护的进程身份、状态、子进程和结束原因均记账，ws02以独立CPU父子进程验证“父暂停、子继续、可恢复”。
# 项目资源优先级补充

项目allocation预留数与基础模型补卡上限由独立的`research_gpu_roles_v1`策略配置。基础模型临时使用项目卡时仍计入项目预留，不能与普通基础模型池重复计数。旧科学worker保持原不可变源码；新CPU管理入口只延伸调度模块路径，不替换数据适配与训练依赖。

新allocation owner仅在项目依赖已齐且共存资源有余量时，执行有时限的独立前后向、更新及恢复预检。通过后只向让位的基础模型写入暂停请求，待断点完成、旧step退出，再按原run ID返回候选池。失败或资源不足保留健康旧任务。旧owner不热更新，随正常allocation轮换升级；不能把代码验收写成已发生实际项目抢占。
